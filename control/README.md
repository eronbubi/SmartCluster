# control

The SmartCluster control center: Go backend with Postgres.

## Packages

| Package | Purpose |
|---|---|
| `cmd/smartcluster-control` | CLI: `serve`, `token create`, `version` |
| `internal/server` | Wiring: database, cluster identity, listeners, maintenance |
| `internal/db` | Postgres pool and goose migrations (`db/migrations`) |
| `internal/store` | Queries: cluster, encrypted secrets, join codes, nodes, stats with partitions and 5-minute rollups |
| `internal/secrets` | Master key file and AES-256-GCM for secrets in the database |
| `internal/pki` | Cluster CA with name constraints, server and agent certificates |
| `internal/enroll` | `POST /agent/v1/enroll` |
| `internal/agentgw` | Agent WebSocket (mTLS), hello, stats, signed commands, certificate renewal |
| `internal/live` | App WebSocket `/api/v1/live` with topic subscriptions |
| `internal/api` | REST API `/api/v1` |
| `internal/testdb` | Embedded Postgres 18 for tests |

Queries are hand-written with pgx instead of generated by sqlc (ARCHITECTURE.md
mentions sqlc): sqlc's Postgres parser needs cgo, which the Windows
development setup does not have. Every query is covered by tests against a
real Postgres.

## Listeners

| Address | Default | Content |
|---|---|---|
| `--agent-addr` | `:8444` | enrollment, agent WebSocket, renewal. TLS 1.3, client certificates of the cluster CA |
| `--api-addr` | `127.0.0.1:8443` | REST API, live WebSocket, web app. **No login before milestone b**, therefore localhost by default |

## Run locally

```bash
go run ./tools/devdb            # terminal 1: Postgres 18 in ./.data/devdb
export SC_DATABASE_URL='postgres://smartcluster:dev@127.0.0.1:54329/smartcluster?sslmode=disable'
export SC_DATA_DIR=./.data/control
go run ./control/cmd/smartcluster-control serve
go run ./control/cmd/smartcluster-control token create
```

## Tests

```bash
go test ./control/...
```

The first run downloads the Postgres binaries into the embedded-postgres cache.
